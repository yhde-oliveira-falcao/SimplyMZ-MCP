## Follow-up: release-blocking bug found by Final Verification work (2026-10-06)
While writing the D16 no-network test, a stack trace showed pyteomics' mzML parser loading
the PSI-MS vocabulary through **psims**, which was only a dev/fixtures dependency. In a
clean install (verified in a fresh venv) every load_run failed with PyteomicsError: the
earlier smoke test only called server_info and never parsed a file. Fixed in 337618e:
psims is a core dependency; the vocabulary is loaded once from psims' vendored copy and
passed to `mzml.MzML(..., cv=...)` directly, because `mzml.read()` silently drops its `cv`
argument (pyteomics 5.0.1). That also removed 12 network attempts to purl.obolibrary.org
per file. The installed-package smoke test (AC4, release workflow) now loads an mzML.
Lesson recorded: an earlier ad-hoc check printed "no network used" without counting
attempts; psims had silently fallen back after the blocked connection.
